# ADR 0003: Изоляция runtime и read-only доступ к Capella в P0

- Статус: принято
- Дата: 2026-09-02
- Область: P0

## Контекст

Пилот обязан одновременно закрепить StrictDoc `0.29.0` и capellambse `0.8.0` на
Python 3.12. Эти версии нельзя корректно установить в одно окружение: StrictDoc требует
`python-datauri >=2.1.1,<3`, а capellambse `0.8.0` — `python-datauri >=3.0.2`.
Обход resolver-а дал бы импортируемую, но неподдерживаемую комбинацию.

Кроме того, capellambse `0.8.0` существует как официальный Git tag/release, но не как
точная публикация PyPI. P0 должен только читать модель и рендерить представления, не
вызывая сохранение.

## Решение

Создаются два изолированных окружения Python 3.12, разрешаемых одним `uv.lock`:

| Окружение | Extra | Назначение |
|---|---|---|
| `.venv` | `strictdoc-runtime` | FastAPI, StrictDoc `0.29.0`, тесты и экспорты |
| `.venv-capella` | `capella-runtime` | отдельный read-only worker capellambse `0.8.0` |

Extras объявлены конфликтующими и никогда не активируются совместно. capellambse
фиксируется на официальном commit
`2abba5cd8922a306cdb735a9c19bcfefdb74a7e8` тега `v0.8.0`; lock-файл фиксирует commit
и все транзитивные зависимости.

Основной backend не импортирует capellambse. Он запускает отдельный worker интерпретатором
из `.venv-capella` списком аргументов, с `shell=False`, timeout, контролируемым cwd и
минимальным окружением. Один запрос выполняется одним процессом и возвращает
версионированный JSON-ответ; рабочие логи идут в stderr и не смешиваются с протоколом.
Допустимые операции worker-а ограничены:

- открыть настроенную модель;
- построить read-only индекс UUID, типа, слоя, имени, описания, parent, отношений и
  allocations;
- перечислить диаграммы;
- получить SVG/PNG представление;
- вычислить fingerprint и диагностику.

Worker не предоставляет операции `save`, mutation или произвольного исполнения кода.
Путь модели проверяется относительно project root до запуска и ещё раз в worker-е.
Перед индексированием/рендерингом и после него основной процесс вычисляет SHA-256 всех
файлов модели; несовпадение является ошибкой P0.

`doctor` проверяет Python 3.12, наличие обоих окружений, фактические версии пакетов,
commit capellambse и успешный handshake протокола. Штатная работа не требует сети.

## Рассмотренные альтернативы

### Одно окружение с принудительно выбранной версией `python-datauri`

Отклонено: нарушает declared dependencies одной из точных версий и делает результат
невоспроизводимым.

### Обновить capellambse или StrictDoc

Отклонено: целевые версии заданы критериями пилота. Совместимая более новая комбинация
может рассматриваться отдельным ADR после P0.

### Загружать capellambse в процесс FastAPI динамически

Отклонено: import isolation не решает конфликт установленных зависимостей и повышает
риск утечки изменяемого состояния между запросами.

### Контейнер для Capella adapter

Отклонено для локального пилота как избыточная эксплуатационная зависимость. Граница
процесса уже обеспечивает нужную изоляцию.

## Последствия

Положительные:

- обе целевые версии используются без нарушения их dependency constraints;
- падение или утечка состояния capellambse изолированы от FastAPI;
- протокол worker-а легко подменить fixture adapter-ом в тестах;
- SHA-256 предоставляет фактическое доказательство read-only поведения.

Отрицательные:

- установка и диагностика поддерживают два окружения;
- запуск отдельного процесса добавляет задержку, поэтому допустим только производный
  cache с явными состояниями `loading`, `ready`, `stale` и `error`;
- Python-объекты capellambse нельзя передавать напрямую, их нужно нормализовать в JSON.

## Проверка решения

- lock/resolver test подтверждает невозможность совместной активации extras;
- worker handshake сообщает Python 3.12 и capellambse `0.8.0`;
- unit-тесты отклоняют неизвестную операцию и путь вне project root;
- live-тест сравнивает полный набор SHA-256 до/после чтения и рендеринга;
- при отсутствии легальной реальной модели результат записывается как
  `REAL CAPELLA TEST: NOT EXECUTED`, без fixture-доказательств вместо него.
