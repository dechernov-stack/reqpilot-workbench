# ADR 0005: Границы fixture mode, отчётов и локальной безопасности

- Статус: принято
- Дата: 2026-09-02
- Область: P0

## Контекст

CI и разработка frontend должны работать без установленной Eclipse Capella и без
лицензионных файлов реальной модели. При этом fixture нельзя выдавать за доказательство
интеграции с Capella. Граф, матрицы и combined HTML объединяют данные из нескольких
источников и также не должны становиться скрытым хранилищем. Локальный характер пилота
не отменяет защиту от path traversal, небезопасных subprocess и активного содержимого
в отчётах.

## Решение

### Граница fixture

Fixture adapter включается только явной настройкой `fixture.enabled`; автоматического
fallback из live mode нет. Он читает `fixtures/architecture-fixture.json`, повторяет
blueprint насосной станции, но:

- не создаёт `.capella`, `.aird`, `.melodymodeller` или `.bridgetraces`;
- всегда возвращает состояние `fixture`, отличное от `ready` live adapter-а;
- добавляет видимую метку «Демо-архитектура, не загруженная из Capella» в верхнюю панель,
  архитектурные экраны, диагностику и combined HTML;
- не засчитывается как live integration, UUID/SVG или read-only доказательство;
- не порождает вымышленные скриншоты и файлы модели.

При отсутствии реальной модели отчёт обязан содержать точную строку
`REAL CAPELLA TEST: NOT EXECUTED`. Fixture tests при этом могут и должны проходить
отдельно.

### Производные представления и combined HTML

Graph, matrices, coverage, impact и exports получают immutable snapshot с fingerprints
StrictDoc, Capella/fixture и trace-links. Результаты не принимаются обратно как
канонический ввод.

Combined HTML — автономный производный отчёт. Он содержит project info, coverage,
таблицы требований и links, uncovered/broken списки, выбранные матрицы, доступные
миниатюры диаграмм, версии и fingerprints. CSS и изображения встраиваются; CDN,
внешние URL и runtime network requests запрещены. Отчёт явно указывает режим источника
архитектуры и graph revision.

### Локальная безопасность

- FastAPI слушает только `127.0.0.1`; широкого CORS и внешней telemetry нет;
- auth не имитируется в P0 и остаётся P1;
- все входные пути проходят `resolve` и containment-проверку внутри project root;
- symlink escape и неизвестные файлы отклоняются;
- subprocess получает только allowlisted операции и список аргументов, всегда
  `shell=False`, с timeout и ограниченным окружением;
- пользовательский HTML-текст экранируется, а SVG/HTML не получают script, event
  handlers или внешние resource references;
- P0 никогда не открывает файлы Capella на запись;
- auto-commit, reset и force checkout отсутствуют; показываются только branch и dirty
  status;
- кеши, временные файлы и `.reqpilot/backups` исключаются из публикации и имеют
  ограниченную ротацию.

## Рассмотренные альтернативы

### Автоматически включать fixture при ошибке live model

Отклонено: пользователь может принять демонстрационные данные за реальную модель.
Ошибка live adapter-а должна оставаться видимой и требовать явного переключения режима.

### Генерировать тестовые `.capella`/`.aird`

Отклонено: такие файлы не являются доказательством модели Capella и нарушают запрет на
фабрикацию артефактов.

### Хранить объединённый граф или combined HTML как рабочую базу

Отклонено: производное представление устаревает и дублирует три источника истины.

### Загружать библиотеки и изображения отчёта с CDN

Отклонено: отчёт перестаёт быть автономным, раскрывает данные внешним узлам и не
работает офлайн.

### Считать loopback достаточной защитой

Отклонено: локальная страница всё равно обрабатывает недоверенные поля, пути, YAML и
SVG, а subprocess остаётся границей исполнения.

## Последствия

Положительные:

- UI и CI воспроизводимы без Capella, не искажая статус интеграции;
- любой combined report можно проверить по fingerprints и полностью воспроизвести;
- приложение работает офлайн и имеет небольшую поверхность атаки;
- отсутствие live-модели выражается честным `NOT EXECUTED`, а не ложным PASS.

Отрицательные:

- fixture mode требует постоянной визуальной маркировки во всех представлениях;
- live error не скрывается удобным fallback и требует настройки пользователя;
- санитизация SVG/HTML может удалить активные или внешние элементы исходной диаграммы;
- производные кеши нужно инвалидировать при каждом изменении fingerprint.

## Проверка решения

- e2e-тест ищет fixture banner на каждом архитектурном и отчётном экране;
- live error test подтверждает отсутствие автоматического fallback;
- отчёт открывается офлайн и не содержит внешних ресурсов или исполняемых script;
- security tests отклоняют traversal, symlink escape и неразрешённую subprocess-операцию;
- проверка Git diff подтверждает отсутствие созданных или изменённых файлов Capella.
